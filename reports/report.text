GRANNIES HEALTHBAR — IMPORTANT PROJECT REPORT

Implemented
- Flutter Android project named grannies_healthbar; Android 9+ (API 28).
- Mostly white theme with soft green/red accents, rounded panels, illustrated role buttons, sliding welcome banners, animated buttons and page transitions.
- First-time role selection. A permanent-per-install four-character code uses secure randomness, time and available device details. No MAC address is used, as confirmed.
- Grandma: underlined code, WhatsApp sharing with Android share fallback, copy button, automatic GET pairing checks, saved care plan and daily medicine schedule.
- Helper: four code boxes, cached questionnaire with back/next transitions, age/names, multiple medicines and multiple daily times, local save then automatic server sync.
- Daily medicine schedule on both dashboards. Grandma SOS is visibly locked and does not place calls.
- Helper family panel supports an Android document-picker image, automatic centered 16:9 crop, 1280x720 JPEG resize, private storage and restoration after restart.
- Onboarding progress, role, identity, care plan, API address and photo path are saved in private app storage using queued atomic writes. Failed server saves remain visibly pending with retry.

API
- Default address: https://undrdsk0m2.pythonanywhere.com/. Editable from connection settings; API_BASE_URL is also supported as a build-time initial default. Existing saved addresses take precedence and can be updated in connection settings.
- GET / parses the supplied FastAPI newest-first list of text/date/time records; malformed rows are skipped. Matching uses the exact grandma code.
- POST /{text} sends URL-encoded JSON in one path segment, with no request body, matching the supplied FastAPI code.
- Payload: {"AB23--XY89":{"granmasAge":74,"granmasName":"Rose","childName":"Sam","Medicenes":{"Vitamin D":["08:00","20:30"]}}}
- Arrays make the originally sketched medicine times valid JSON. Backend field spelling is preserved.
- POST responds before its database write completes, so the app verifies persistence through GET before clearing pending sync.
- Plans are limited to 1,000 characters to respect the declared text field. Names cannot contain / because the current API uses a single path parameter.
- On Android, 127.0.0.1 means the Android device. For a server on the development computer, run: adb reverse tcp:8000 tcp:8000. The Python server can remain bound to 127.0.0.1:8000.

Important limits / next steps
- Four-character codes can collide. The current API cannot reserve codes or enforce uniqueness. Server-side registration/collision handling is required before real multi-user deployment.
- The code remains fixed across restarts and app upgrades. Clearing app data or uninstalling removes local storage; permanence across reinstall requires server-backed identity.
- Use test information with the supplied API: it has no authentication/access controls, GET exposes all rows, and POST puts health data in URLs. A future production server needs authenticated access, HTTPS and JSON request bodies. HTTP is currently enabled for local development.
- Daily times use each phone's local timezone. No background notification alarms, dose tracking, emergency-call behavior or specific-date schedules are implemented in this version.
- Photos are center-cropped automatically; interactive crop-position adjustment is not included.
- Release builds currently use Flutter's development signing configuration. Set up a private release key before publishing.
